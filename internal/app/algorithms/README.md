# Алгоритмы балансировки нагрузки

## Алгоритм Round Robin

### Основная концепция

Алгоритм **Round Robin** (Круговой алгоритм) — это один из самых простых и распространенных алгоритмов балансировки нагрузки. Его основная задача — распределить входящие HTTP-запросы между серверами в пуле **циклически**, по очереди.

### Как это работает

1.  **Список серверов:** Балансировщик содержит заранее настроенный список (пул) бэкенд-серверов (например, `[Server A, Server B, Server C]`).
2.  **Указатель:** Балансировщик ведет внутренний указатель на следующий сервер, который должен получить запрос.
3.  **Обработка запроса:**
    *   Приходит **Запрос №1** → направляется на **Server A**. Указатель перемещается на Server B.
    *   Приходит **Запрос №2** → направляется на **Server B**. Указатор перемещается на Server C.
    *   Приходит **Запрос №3** → направляется на **Server C**. Указатель перемещается на Server A.
    *   Приходит **Запрос №4** → направляется на **Server A**. Цикл повторяется.


## Взвешенный Round Robin (Weighted Round Robin)

Это важная модификация, устраняющая ключевой недостаток базового алгоритма.

*   **Принцип работы:** Каждому серверу в пуле присваивается числовой **вес (weight)**. Сервер с более высоким весом получает больше запросов.
*   **Пример:**
    *   `Server A` (`weight=4`)
    *   `Server B` (`weight=2`)
    *   `Server C` (`weight=1`)
    *   **Идеальное распределение:** Запросы будут распределяться в пропорции 4:2:1. На каждые 7 запросов сервер A получит 4, сервер B — 2, а сервер C — 1.
